# Проверка соответствия первичных артефактов

Проверены требования памятки, строка варианта 4 и пояснение к нему в пособии, пользовательские бизнес-домен и маппинг. Образцы репозиториев использованы как примеры состава и оформления.

**Вывод:** после перечисленных ниже исправлений комплект соответствует проверенным требованиям этапа первичных артефактов. Дисциплины варианта 4 сохранены. Программа, результаты прогонов и экономическое обоснование относятся к следующим этапам.

| Требование | Результат проверки |
|---|---|
| ИБ, ИЗ2, ПЗ1 | Независимая генерация, равномерные интервалы, экспоненциальное обслуживание |
| Д1ОЗ1 | Кольцевой поиск от УБ; после записи указатель перемещается; при выборке сдвига нет |
| Д1ОО4 | Вытесняется последняя старая ожидающая заявка; новая принимается; отказ относится к источнику жертвы |
| Д2П2 | Поиск свободного прибора от УП по кольцу; УП изменяется после назначения |
| Д2Б4 | Одна заявка источника с минимальным номером; внутри источника последняя поступившая, как в пояснении варианта 4 |
| ОД1, ОР2 | Календарь и состояние в пошаговом режиме; графики показателей по параметрам в автоматическом |
| Общий сиквенс | Показаны оба типа событий, альтернативы, переполнение, ожидание и последующее назначение |
| Отдельные ключевые случаи | HappyFlow, переполнение с последующей обработкой, приоритет и выбор прибора |
| Классы | Методы с аргументами и результатами, приватные поля, ссылки на общие ресурсы |
| Блок-схема | Дорожки, свободный/полный буфер, занятые/свободные приборы, генерация/завершение |
| ArchiMate | Дополнительная схема бизнес-процесса и поддерживающих компонентов |
| Показатели из пособия | Счётчики, вероятность отказа, средние времена, дисперсии ожидания и обслуживания, загрузка приборов |

## Исправления по результатам повторной проверки

1. В общий сиквенс добавлен явный выход из цикла назначений через локальный флаг вместо UML-фрагментов break. Модель продолжает обрабатывать календарь при отсутствии свободного прибора.
2. Инициализация и запуск разделены; первые генерации показаны вызовами методов, существующих на диаграмме классов.
3. В Statistics добавлены суммы и суммы квадратов для дисперсий ожидания и обслуживания. В описание и ExperimentRunner добавлены целевые точность 10% и доверительная вероятность 0,9 из пособия; их достижение предстоит проверять на работающей модели.
4. В конкретном примере переполнения начальный УБ исправлен на 3: последняя старая заявка находится в слоте 2. Жертва и итоговое состояние не изменились.
5. Пример выбора с двумя свободными приборами явно обозначен искусственным снимком для проверки dispatch, поскольку обычная модель не оставляет свободные приборы при наличии очереди.
6. Для подробных сценариев указано отсутствие промежуточных поступлений там, где последующее состояние зависит от этого условия.

Ссылки на образцы приведены в [основном описании](primary-artifacts.md). Правила чужих вариантов не подменяют дисциплины варианта 4. Отличия в числе вспомогательных классов, именах методов и расположении файлов допустимы: памятка не задаёт единственный шаблон архитектуры.
