# СМО «Сервис обработки аналитических заданий спортивных клубов»

**Вариант 4 · Добров М. Г. · группа 5130904/40106**

Этап 2 — первичные артефакты проектирования. Комплект подготовлен по бизнес-домену и маппингу автора, пособию СМО 2025 года и памятке к упражнениям.

**Код:** `ИБ ИЗ2 ПЗ1 Д1ОЗ1 Д1ОО4 Д2П2 Д2Б4 ОР2 ОД1`.

Клиентские системы трёх спортивных клубов отправляют задания на расчёт статистики матчей и тренировок. Заявки поступают в общий кольцевой буфер ограниченной ёмкости, затем передаются свободным серверным обработчикам. При переполнении вытесняется последняя ранее принятая ожидающая заявка. Приоритет клуба определяется номером: **И1 > И2 > И3**.

## Расшифровка варианта

| Код | Правило |
|---|---|
| ИБ | Источники бесконечные: генерация не зависит от завершения предыдущих заявок |
| ИЗ2 | Интервал источника i: `aᵢ + (bᵢ − aᵢ)·U`, `U ∈ [0,1)` |
| ПЗ1 | Время обслуживания прибором j: `−ln(U)/μⱼ`, `U ∈ (0,1)`, `μⱼ > 0` |
| Д1ОЗ1 | Поиск свободного места по кольцу от УБ; после записи в слот s: `УБ := s mod K + 1` |
| Д1ОО4 | При полном буфере заменить последнюю ранее поступившую в него заявку новой; отказ старой заявке |
| Д2П2 | Поиск свободного прибора по кольцу от УП; после назначения прибору j: `УП := j mod M + 1` |
| Д2Б4 | Одна заявка источника с минимальным номером; внутри источника — последняя поступившая |
| ОР2 | Графики показателей по значениям параметров в автоматическом режиме |
| ОД1 | Календарь событий, буфер, состояние приборов и источников, УБ и УП в пошаговом режиме |

## Существенные решения

1. Все заявки проходят через буфер. Диспетчер постановки знает только буфер и статистику. После размещения модель вызывает диспетчер выбора в то же модельное время.
2. Диспетчер выбора работает после поступления заявки и после освобождения прибора. Пока есть буферные заявки и свободные приборы, он назначает по одной заявке за итерацию.
3. Вытесняется последняя по времени **ожидающая** заявка до вставки новой, независимо от приоритета. При равных временах используется глобальный порядковый номер вставки `queueOrder`.
4. Позиция в массиве не определяет возраст заявки. Выборка не сдвигает остальные элементы и не меняет УБ.
5. При совпадении времени сначала обрабатываются завершения обслуживания, затем генерации; внутри типа — по номеру прибора/источника и порядковому номеру события.
6. Ожидание реализуется переходом к следующему событию календаря. Приборы продолжают работу, источники продолжают генерацию. Занятый прибор не является отказом.
7. Пакеты, прерывание обслуживания и повторная отправка вытесненных заданий отсутствуют.

## Пересборка

Нужны Java 11+, PlantUML 1.2026.9 и Python с пакетами `python-docx`, `Pillow`. Рендеринг локальный; `!pragma layout smetana` позволяет обойтись без установленного Graphviz. Библиотека ArchiMate поставляется внутри PlantUML.

```powershell
python tools/build_artifacts.py --plantuml-jar C:\tools\plantuml.jar
```

Если по умолчанию запускается старая Java, укажите путь к новой через `--java "C:\Java\jdk-21\bin\java.exe"`. Зависимости Python: `python -m pip install -r tools/requirements.txt`.

Скрипт проверяет синтаксис, создаёт SVG/PNG, HTML-галерею и Word-документ. Исходные пользовательские DOCX не изменяются. Публикация и команды Git в сборке отсутствуют.

PDF и DOCX используются как локальные копии для просмотра и защиты и исключены из Git через `.gitignore`. В репозитории публикуются Markdown, исходники PlantUML и изображения диаграмм.
